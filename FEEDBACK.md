# Feedback — gunnchOS Ecosystem

**Public front door for RC1:** use this portal repository’s issue forms.  
**Security vulnerabilities:** always use [private GitHub Security Advisories](https://github.com/gunnchOS3k/gunnchos-research-portal/security/advisories/new) — never public issues.

## Quick links

| Kind | Open |

| Feature | [Feature request](../../issues/new?template=feature.yml) |

Relative form URLs resolve on GitHub; from a clone, prefer **Issues → New issue**.

## What to include

- Component or lane (Portal, Device OS, WAIKE, gunnchAI, Hardware, Research, Experiences)
- Version / SHA / device when known (`v1.0.0-rc.1`, Pixel, browser)
- Steps, expected vs actual (bugs)
- No secrets, tokens, PII, or private competition / field datasets

## How feedback becomes releases

1. Triage — [docs/feedback/FEEDBACK_TRIAGE.md](docs/feedback/FEEDBACK_TRIAGE.md)

## Component repos

File portal issues for cross-cutting / unsure routing. Component repos may have additional templates; preserve those for specialized workflows. Always prefer this portal for first public contact during RC1.

## In-app feedback

| Class | Status for RC1 |
|---|---|

| `V1_REQUIRED` | Stable in-app entry points before final `v1.0.0` |
