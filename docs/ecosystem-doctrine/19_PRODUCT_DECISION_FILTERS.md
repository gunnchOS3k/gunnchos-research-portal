# Product Decision Filters

Use these before approving major features or architecture changes.

## Coherence
Does it strengthen the feeling of one ecosystem?

## User clarity
Can a non-expert understand what it does and where it belongs?

## Privacy
Does it preserve private/shared/public boundaries?

## Continuity
Does it work with the device/host philosophy?

## Learning
Can the user understand or grow from it?

## Equity
Does it lower or raise barriers to access?

## Offline/resilience
What happens when connectivity disappears?

## Accessibility
Can different users actually use it?

## Quality
Does it feel like a real product, not a demo?

## Evidence
Can we honestly prove the claim we want to make?

## Rights
Do we have the right to ship the content/integration?

## Scope
Does it belong in the current release?

## Maintainability
Can future contributors understand and reproduce it?

## Decision shortcut

Prefer a feature when it makes the ecosystem:
- more coherent;
- more understandable;
- more useful;
- more personal;
- more accessible;
- more truthful.

Be skeptical when it mainly makes the system:
- more complicated;
- more fragmented;
- harder to validate;
- harder to explain;
- more dependent on unproven assumptions.
