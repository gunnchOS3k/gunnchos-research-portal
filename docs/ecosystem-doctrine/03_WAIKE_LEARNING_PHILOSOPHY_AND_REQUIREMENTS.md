# WAIKE Learning Philosophy and Requirements

## Role

WAIKE is the native learning system of the ecosystem.

It should learn from Canvas, Blackboard, Brightspace, Gradescope, and other LMS products without becoming a clone of them.

## Philosophy

Learning should feel connected to the technology being learned.

A networking student should see networking systems.

A hardware student should interact with hardware artifacts.

A game student should work with games.

A research student should work with research systems.

## Required concepts
- offline learning;
- durable sync;
- assessments;
- labs;
- grading;
- mastery;
- portfolios;
- groups;
- instructor roles;
- student roles;
- secure identity;
- standards interoperability;
- curriculum from WAIKE research ops;
- gunnchAI assistance.

## Learning experience requirements

### Beginner legibility
A newcomer should understand what to do next.

### Expert depth
The system must not flatten advanced technical content into oversimplification.

### Evidence
Students should be able to preserve artifacts of learning.

### Mastery
The platform should help distinguish “submitted” from “understood.”

### Offline
Loss of connectivity should not automatically end learning.

### Device continuity
Learning should work across the device/host ecosystem where validated.

## gunnchAI relationship

gunnchAI should be able to:
- explain;
- tutor;
- help plan;
- review;
- give feedback;
- support instructors;
- assist with labs/assignments within policy.

WAIKE must still retain:
- source-of-truth course state;
- permissions;
- grading authority;
- auditability.

## Current state
Substantial LMS/offline/security/assessment work exists.

## Future state
A learning operating environment spanning school, professional development, self-study, labs, research, and portfolio creation.

## Boundary
Do not claim institutional certification, K-12 deployment approval, or complete authored curriculum where authentic evidence does not exist.
